GateWay

הדרך אל מחוץ לרשת המקומית

לאן נשלח המידע?

במחשב ברשת מוגדרות כתובת IP ומסכת רשת. לפי שני הפרטים האלה נקבע: האם היעד נמצא ברשת המקומית, או ברשת אחרת?

אם היעד נמצא באותה רשת, המידע נשלח אליו ישירות. כתובת ה-MAC של היעד מתקבלת באמצעות ARP, וה-Frame נשלח אליו.

אבל מה קורה כשהכתובת נמצאת מחוץ לרשת המקומית?

המחשב שלנו192.168.1.42
יעד:8.8.8.8

8.8.8.8 היא כתובת של שרת של Google באינטרנט. לפי מסכת הרשת, הכתובת 8.8.8.8 אינה חלק מהרשת המקומית. כתובת היעד ידועה, אבל היעד נמצא ברשת אחרת. לכן נדרשת כתובת שדרכה המידע יוצא מהרשת המקומית.

רק הצעד הבא

כדי לשלוח מידע ל-8.8.8.8, אין צורך בהגדרת המסלול המלא במחשב. נדרשת כתובת הצעד הבא. בשביל זה קיימת כתובת ה-GateWay.

Computer192.168.1.42
GateWay192.168.1.1
Destination8.8.8.8

היעד אינו מקומי, ולכן ה-Frame נשלח ל-GateWay. ה-GateWay הוא בדרך כלל ממשק של נתב שנמצא באותה רשת מקומית של המחשב. הנתב מעביר את המידע הלאה, לכיוון היעד.

אין צורך בכתובות של כל הנתבים שבדרך. הכלל: אם היעד אינו ברשת המקומית, המידע נשלח ל-GateWay.

נקודה חשובה: כתובת ה-IP של היעד עדיין נשארת 8.8.8.8. המחשב אינו משנה את יעד ה-IP לכתובת של ה-GateWay. מה שמשתנה ברשת המקומית הוא יעד ה-Ethernet Frame: המחשב שולח את ה-Frame אל כתובת ה-MAC של ה-GateWay. לכן, לפני שהוא יכול לשלוח, הוא עשוי להשתמש ב-ARP כדי לגלות את כתובת ה-MAC של ה-GateWay.

GateWay

GateWay הוא נקודת היציאה של המכשיר מהרשת המקומית אל רשתות אחרות.

כאשר היעד נמצא בתוך הרשת המקומית, אין צורך ב-Default GateWay לצורך ההגעה אליו. כאשר היעד נמצא מחוץ לרשת המקומית, המחשב שולח את המידע ל-Default GateWay, והנתב ממשיך משם.

יעד מקומישולחים ישירות ליעד
יעד מרוחקשולחים ל-GateWay

וזה גם מסביר מדוע DHCP נותן למחשב לא רק כתובת IP ומסכת רשת, אלא גם את כתובת ה-GateWay. בלי כתובת IP אין למחשב כתובת ברשת. בלי מסכת רשת אי אפשר לקבוע מה נחשב מקומי. ובלי GateWay אין צעד ראשון אל מחוץ לרשת המקומית.

בלי שער ברירת מחדל - Default GateWay, ובהיעדר הגדרת ניתוב אחרת, אפשר לתקשר רק בתוך הרשת המקומית.
